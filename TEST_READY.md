# E2E Test Runner and Coverage Summary

This file serves as the main entry point and documentation for executing the E2E tests for the Savesnapfast project.

---

## Test Runner Commands

To execute the full verification suite, run the following commands in the project root:

### 1. Static Audit
Executes static analysis of codebase patterns, configurations, navigation links, and sitemaps.
```bash
node audit_check.cjs
```

### 2. Build Output E2E Verification
Parses built pages and assets in the `dist/` directory to verify canonicals, hreflangs, robots.txt, and thin-content exclusions.
```bash
node verify_build.cjs
```

---

## E2E Testing Coverage Summary

Our E2E test coverage spans 4 distinct tiers, validating both static files and dynamically built outputs:

### Tier 1: Feature Coverage (Pass/Fail)
- **SEO Config**: Verifies trailing slash settings and canonical URL consistency.
- **Hreflang Tags**: Checks presence of hreflang attributes for supported languages.
- **Static Assets**: Assures all required static files (`favicon.ico`, `manifest.json`, etc.) exist.
- **Robots.txt**: Verifies crawlers are blocked from disallowed resources.

### Tier 2: Boundary/Corner Cases
- **Trailing Slash Normalization**: Ensures trailing slashes are disallowed for canonical/hreflang tags.
- **Language Prefixes**: Verifies correct file layouts for lang pages (e.g. `/ar/mp3`, `/es/about`).
- **Sitemap index**: Verifies sitemap index correctly dynamically resolves from `dist/`.

### Tier 3: Cross-Feature Interactions
- **Thin Content vs Sitemap**: Programmatically counts blog posts by locale in `src/content/blog` and checks that listing pages with $< 2$ posts are excluded from `sitemap-0.xml`.
- **Hreflang Self-Reference**: Dynamically parses blog post pages (e.g. `/blog/[slug]`) to guarantee that their self-referencing hreflang tags point to the exact absolute URL of the page itself instead of defaulting to the category index.

### Tier 4: Real-World Workload
- **Full Build Integrity**: Runs verification against build output generated by the Astro production build.
- **Strict Exit Codes**: Both check scripts return non-zero exit codes upon failure, making them integration-ready.
